# TOEIC learning implementation plan

**Goal:** Replace the health app with a Vietnamese daily TOEIC learning application and push the verified result to the existing GitHub remote.
**Architecture:** Existing Supabase email authentication; React client application; transactional PostgreSQL RPC for review updates, mistake streaks and session accounting. Read-only public preview uses extracted data with isolated local storage. No fabricated vocabulary.
**Tech stack:** Next 16.4 / React 19 / TypeScript / Supabase.
**Spec:** User requirements in this conversation, Steps 0–5.

## Constraints and rulings
- User authorized completing all steps, push and deletion of the old public app data; preserve auth users.
- Source has 596 unique words, not 600. Keep nullable source fields, disclose count, do not generate meanings or examples.
- Existing work is in D:/HEALTH; continue in place on a feature branch to preserve all prior changes and environment.
- A study session is explicitly started and finished; only one correct-streak increment per word per completed distinct session. Wrong resets streak immediately. A completed session must contain real answers. Daily queue prioritizes mistakes, then due reviews, then new words.
- Fill quiz requires a source example containing the word; PDF has none, so provide the mode with a truthful empty state, never invent examples.
- Supabase migration is additive after explicit targeted reset. Auth and system schemas untouched.

## Tasks
- [ ] Domain: typed word/progress/session/settings models; SM-2, daily queue, quiz helpers, dashboard statistics; focused unit tests.
- [ ] Database: migration, RLS, atomic review/session RPCs; repeatable seed and SQL RLS checks; safe reset script for verified legacy objects only.
- [ ] UI: five-tab mobile learning app, flashcard swipe/TTS, quizzes, mistakes, filters, sessions summary, dashboard/settings, light/dark and interactive isolated preview.
- [ ] Integration: connect existing auth, Supabase load/RPC/settings and local preview repository; meaningful auth and domain checks.
- [ ] Operations: apply reset/migration/seed on verified project; test/build and browser checks; README/env; commit and push; inspect Vercel deployment.

## Review focus
- Repeat answers in one session must not graduate mistake words; wrong after correct resets eligibility.
- Owner isolation and RPC validation prevent cross-account writes.
- Missing examples, empty queues and absent TTS voices have clear states.
- Async duplicate taps cannot duplicate review counters or session accounting.
- Preview storage must never write authenticated data to the server or imply synchronization.
